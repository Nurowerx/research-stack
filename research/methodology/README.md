# Experimental methodology — NRS-Bench 1.0.0

Research questions: Can TRACE preserve and validate known relationships? Can LOOP repeat semantic outcomes and expose regressions? Can corrections retain their history and scope? Do LENS numerical marks and FRAME interactions agree with source records?

Hypotheses are executable, finite-task expectations: all valid known graph paths survive exchange; invalid import controls are rejected atomically; fixed policies repeat semantic digests; the specified correction improves its designed revision cases without rewriting the original run; chart coordinates match independent formulas; browser operations retain the selected source data. Failure of any assertion fails the relevant command. These are software hypotheses, not population hypotheses.

The protocol uses original fixtures, three prespecified seeds (13, 42, 20261102), six task families, 20 instances per family, and two repeated predict calls per selected case. Independent variables are target policy, correction configuration, split, seed and injected fault. Dependent variables include per-case correctness, unique-case denominators, paired improved/regressed counts, digest agreement, graph reachability, atomic rejection, SVG coordinate error and browser assertion outcomes. Dependency versions, generator, case selection and scoring are controlled. UUIDs and timing are allowed to vary.

Inclusion: all defined cases in each selected split, all committed tests, and explicit malformed or interrupted controls. Exclusion: private datasets, Foundry services, external language models, human participants and claims of production-scale throughput. No failed tests are silently dropped. Affected-case evaluation selects one previously identified revision failure; its selection bias is disclosed and its score is never substituted for full-split performance.

Accuracy is the number of correct unique cases divided by eligible unique cases. Repeat calls test output consistency and are not additional independent observations. Paired comparisons require the same benchmark version and split and disclose partial overlap. The finite fixture census has no estimated sampling uncertainty; no significance test or accuracy confidence interval is reported. The normal-interval visualization fixture has its own explicit known-variance mathematical assumptions. Runtime seconds and RSS snapshots are descriptive measurements, not inferential performance estimates.

Negative controls include invalid schema fields, invented evidence citations, missing endpoints, cyclic derivation, conflicting evidence, damaged hashes, duplicate identities, inconsistent version histories, nonproject registration, disputed reviews, heldout-driven corrections, target failure and abrupt process exit. Tests distinguish safe rejection, valid conflicting states and incomplete execution. A hard exit leaves an observable running row; automated recovery is not implemented.

Threats: common authorship of generator, policy and tests; structurally related seeds; one engine and one browser; no human study; developer-controlled reproduction; hardware and cache effects on timing; no authenticated provenance signatures; limited stress scale. Independent SVG formulas and a SciPy interval calculation reduce some shared-code risk but do not eliminate it. An external replication and new task families are recommended before broader claims.

Raw inputs are datasets/synthetic/v1. Transformations are source-controlled policy execution, scoring, unique-case aggregation, paired comparison and rendering. Research observations and source commit are in research/results. Reproduce with the clean-install procedure; retain command logs and report failures with their environment. The original 31 tests are historical baseline evidence, separate from release tests.
